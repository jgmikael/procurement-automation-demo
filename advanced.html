Kytkee JSON-avaimet URI-tunnisteisiin

Semanttinen Kerros: Automaation Yhteinen Kieli

Tekninen yhteys siirtää bittejä; semanttinen yhteentoimivuus tekee niistä samoja faktoja kaikille osapuolille.

📚 SKOS Sanasto

Käsitteet, määritelmät, synonyymit ja kieliversiot

@prefix skos: <http://www.w3.org/2004/02/skos/core#> . @prefix proc: <https://procurement.fi/vocab#> . proc:Tarjoaja a skos:Concept ; skos:prefLabel "Tarjoaja"@fi ; skos:altLabel "Toimittaja"@fi ; skos:prefLabel "Supplier"@en ; skos:definition "Yritys tai yhteenliittymä, joka jättää tarjouksen julkisessa hankinnassa"@fi ; skos:broader proc:Toimija ; skos:related proc:Alihankkija ; skos:exactMatch epo:Supplier .

🔗 OWL/RDF Vocabulary

Koneluettavat luokka- ja ominaisuussuhteet

@prefix owl: <http://www.w3.org/2002/07/owl#> . @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> . @prefix proc: <https://procurement.fi/vocab#> . proc:Tarjoaja a owl:Class ; rdfs:subClassOf org:Organization ; rdfs:label "Tarjoaja"@fi . proc:jättääTarjouksen a owl:ObjectProperty ; rdfs:domain proc:Tarjoaja ; rdfs:range proc:Tarjous ; rdfs:label "jättää tarjouksen"@fi .

✓ SHACL Profiili

Käyttötapauksen validointisäännöt

@prefix sh: <http://www.w3.org/ns/shacl#> . proc:TarjoajaShape a sh:NodeShape ; sh:targetClass proc:Tarjoaja ; sh:property [ sh:path proc:ytunnus ; sh:minCount 1 ; sh:maxCount 1 ; sh:pattern "^[0-9]{7}-[0-9]$" ; sh:message "Y-tunnus pakollinen ja muodossa 1234567-8"@fi ] ; sh:property [ sh:path proc:verotodistus ; sh:minCount 1 ; sh:class proc:Verotodistus ; sh:message "Verotodistus vaaditaan"@fi ] .

🔑 JSON-LD @context

Kytkee JSON-avaimet semanttisiin URI:hin

{ "@context": { "proc": "https://procurement.fi/vocab#", "businessId": { "@id": "proc:ytunnus", "@type": "xsd:string" }, "taxCertificate": { "@id": "proc:verotodistus", "@type": "@id" }, "submittedDate": { "@id": "proc:jättöpäivä", "@type": "xsd:dateTime" } } }

💡 Semanttinen Perusta On Formaattiriippumaton

W3C VC + JSON-LD tekee semanttisen linkityksen erityisen suoraan, mutta myös XML- ja tavalliset JSON-sanomat voidaan liittää samaan perustaan ulkoisilla määrityksillä.

Ratkaiseva linjaus: Suomen ei pidä rakentaa EU-vaatimusta varten erillistä semanttista saareketta. Hankintojen semantiikka on liitettävä kansalliseen yhteiseen semanttiseen perustaan ja yritystiedon laajempaan eurooppalaiseen perustaan.

Agentti ei korvaa oikeudellista prosessia; se käyttää yhteisiä faktoja ja sääntöjä prosessin turvalliseen orkestrointiin.

🛑 Agentin Kovat Rajat

1. Mandaatti: Toimii varmennetulla organisaatio- tai henkilömandaatilla; valtuus on tarkistettavissa ennen jokaista sitovaa toimintoa.

2. Ei keksi faktaa: Ei keksi oikeusperustaa, arviointikriteeriä tai puuttuvaa faktaa; epävarmuus johtaa lisätiedon pyyntöön tai eskalointiin.

3. Versionhallitut säännöt: Käyttää versionhallittuja sääntöpalveluja ja validoituja datatuotteita; generatiivinen malli ei yksin tee kelpoisuus- tai vertailupäätöstä.

4. Audit trail: Säilyttää tapahtuma-, päätös-, tietolähde- ja hyväksyntäketjun jäljitettävyyden tukemiseksi.

5. Ihminen vastuussa: Ihminen säilyy vastuullisena erityisesti harkinnassa, neuvottelussa, poikkeamisessa ja oikeusvaikutteisessa lopullisessa päätöksessä.

Agentti → Sääntö → Ihminen -malli

1. Agentti Ehdottaa

"Tarjoaja täyttää kaikki 5 vaatimusta. Ehdotan siirtymistä tarjousten vertailuun."

agent.propose("PROCEED_TO_EVALUATION", reasoning="All eligibility checks passed")

2. Sääntömoottori Rajaa

Tarkistaa että ehdotus noudattaa sääntöjä ja agentilla on mandaatti

ruleEngine.validate("procurement.rules.v2.4.1", action="PROCEED_TO_EVALUATION") mandateService.check(agent.id, action="PROCEED_TO_EVALUATION") → AUTHORIZED

3. Ihminen Hyväksyy (tai Hylkää)

Ihminen tarkistaa perustelut ja hyväksyy tai pyytää lisäselvitystä

human.approve() → PROCEED // Audit trail: agent proposal + rule validation + human approval → recorded
